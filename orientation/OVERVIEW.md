# FlowInsight, FlowJournal and WatchMoovies: an overview for newcomers

This repo builds **three desktop apps** from Twilight City, Inc. from one codebase: **FlowInsight**, **FlowJournal** and **WatchMoovies** ([`public/app/AppConfig.js:101-107`](https://github.com/twilightcity-net/flow-insight/blob/872b8ac1decccc17531fcb98e3a8ed1f0053e0ec/public/app/AppConfig.js?plain=1#L101-L107)). Each is a build-time variant with its own set of features. They're built with Electron and React. The README pitches the flow apps as giving developers "smart stats for your workflow, to support data-driven learning and improve efficiency of your team" ([`README.md:14`](https://github.com/twilightcity-net/flow-insight/blob/872b8ac1decccc17531fcb98e3a8ed1f0053e0ec/README.md?plain=1#L14)). It works with two Twilight City services: **Gridtime**, a metrics/REST backend, and **Talknet**, a realtime socket server ([`README.md:16`](https://github.com/twilightcity-net/flow-insight/blob/872b8ac1decccc17531fcb98e3a8ed1f0053e0ec/README.md?plain=1#L16)). The README describes only *FlowInsight*. At this commit the configured build is **FlowJournal** 0.8.0, in `package.json` ([`package.json:2-5`](https://github.com/twilightcity-net/flow-insight/blob/872b8ac1decccc17531fcb98e3a8ed1f0053e0ec/package.json?plain=1#L2-L5)), and `AppConfig.appType` selects the FlowJournal variant ([`public/app/AppConfig.js:5`](https://github.com/twilightcity-net/flow-insight/blob/872b8ac1decccc17531fcb98e3a8ed1f0053e0ec/public/app/AppConfig.js?plain=1#L5)).

This overview is a reader's map, not part of the project. It was written with Bram on 2026-10-26 from the repository as of commit `872b8ac1` (2025-03-03). Every claim cites a file and line at that commit on GitHub (`github.com/twilightcity-net/flow-insight`). Where the repo is silent, this says so rather than guessing. The **Architecture** tab has seven diagrams with click-through detail.

The code is MIT-licensed, but "the logos, artwork, and trademarks … including FlowInsight, WatchMoovies, Monty, and Fervie are not among the things being made available" ([`LICENSE.md:23-25`](https://github.com/twilightcity-net/flow-insight/blob/872b8ac1decccc17531fcb98e3a8ed1f0053e0ec/LICENSE.md?plain=1#L23-L25)).

## How the pieces talk

Electron splits the app in two. The **front end** is React, running in browser windows (`src/`). It draws the screen. The **back end of the front end** is Node, in Electron's main process (`public/`). It makes the web requests to Gridtime and Talknet, and keeps a local LokiJS database as a **cache**, so that every re-render or refresh doesn't go back to the server. The two halves talk only over an **IPC bus** of named events. The front end sends a request across, the back end answers from the cache or fetches and stores first, and the reply comes back across. This framing comes from the maintainers (2026-10-26). The *System*, *A request's round trip* and *Data and state* diagrams show it with code citations.

## What it is

- **Three apps, one codebase.** A developer picks the app by editing `AppConfig.appType` (main process), `FeatureToggle.appType` (renderer) and the identity fields in `package.json`. The code then branches on that choice in about fifty places, covering menus, sidebar items, background jobs and momentum rules. User-facing feature toggles, stored in `~/.flow/settings.json`, refine it further. See the *Three apps, one codebase* diagram.
- **Electron main process**, in `public/`. `electron.js` creates `App` ([`public/electron.js:1-11`](https://github.com/twilightcity-net/flow-insight/blob/872b8ac1decccc17531fcb98e3a8ed1f0053e0ec/public/electron.js?plain=1#L1-L11)), which builds about forty singleton managers on `global.App` ([`public/app/App.js:173-216`](https://github.com/twilightcity-net/flow-insight/blob/872b8ac1decccc17531fcb98e3a8ed1f0053e0ec/public/app/App.js?plain=1#L173-L216)). The rest is organized as:
  - `managers/`, each owning a `controllers/` class that talks REST to Gridtime and keeps an in-memory LokiJS database (`database/`);
  - `windows/`: one class per BrowserWindow;
  - `job/` and `app/App*Job.js`: background loops, including the flow-feed publisher and the heartbeat.
- **React renderer**, in `src/`. One bundle serves every window. A `?view=` query parameter picks the view ([`src/views/ViewManager.js:92-97`](https://github.com/twilightcity-net/flow-insight/blob/872b8ac1decccc17531fcb98e3a8ed1f0053e0ec/src/views/ViewManager.js?plain=1#L92-L97)). `clients/` are renderer singletons that call main-process controllers over IPC. `layout/console/` holds the console UI: journal, circuits, team, buddies, terminal, dashboard and others.
- **LokiJS cache.** The main process keeps an in-memory copy of server data in eleven LokiJS databases. `LOAD_*` fetches from the API fill them, Talknet pushes patch them, and a heartbeat `REFRESH` rebuilds them. Windows read them only through `GET_*` requests to main-process controllers; nothing in `src/` imports LokiJS. Nothing is saved to disk, so every start reloads from the server ([`public/managers/VolumeManager.js:35-79`](https://github.com/twilightcity-net/flow-insight/blob/872b8ac1decccc17531fcb98e3a8ed1f0053e0ec/public/managers/VolumeManager.js?plain=1#L35-L79)). See the *Data and state* diagram.
- **IPC event bus.** `public/events/EventManager.js` and `src/events/RendererEventManager.js` carry named channels. Every main-process dispatch is also sent to every open window ([`public/events/EventManager.js:352-403`](https://github.com/twilightcity-net/flow-insight/blob/872b8ac1decccc17531fcb98e3a8ed1f0053e0ec/public/events/EventManager.js?plain=1#L352-L403)).
- **IDE plugin bridge.** Plugins outside this repo write `active.flow` feeds under `~/.flow/plugins`. The app batches them and posts them to `/flow/input/batch` every 10 minutes ([`public/app/AppFlowPublisherJob.js:22`](https://github.com/twilightcity-net/flow-insight/blob/872b8ac1decccc17531fcb98e3a8ed1f0053e0ec/public/app/AppFlowPublisherJob.js?plain=1#L22), [`public/job/FlowFeedProcessor.js:720`](https://github.com/twilightcity-net/flow-insight/blob/872b8ac1decccc17531fcb98e3a8ed1f0053e0ec/public/job/FlowFeedProcessor.js?plain=1#L720)).
- **Mock API**, in `server/`. An Express app with four `/account/*` routes, used by the API tests ([`server/Server.js:9-43`](https://github.com/twilightcity-net/flow-insight/blob/872b8ac1decccc17531fcb98e3a8ed1f0053e0ec/server/Server.js?plain=1#L9-L43)).
- **Dogfooding config.** The root `flowinsight-config.json` maps this repo's own files into "boxes" (css, electron, renderer, build) ([`flowinsight-config.json:1-57`](https://github.com/twilightcity-net/flow-insight/blob/872b8ac1decccc17531fcb98e3a8ed1f0053e0ec/flowinsight-config.json?plain=1#L1-L57)). That's the per-module config format the app itself reads ([`public/job/CodeModuleConfigHandler.js:21`](https://github.com/twilightcity-net/flow-insight/blob/872b8ac1decccc17531fcb98e3a8ed1f0053e0ec/public/job/CodeModuleConfigHandler.js?plain=1#L21)).

## How it runs

- **Choosing the app:** there is no flag or script for this. Edit the app type in [`public/app/AppConfig.js:5`](https://github.com/twilightcity-net/flow-insight/blob/872b8ac1decccc17531fcb98e3a8ed1f0053e0ec/public/app/AppConfig.js?plain=1#L5) **and** [`src/layout/shared/FeatureToggle.js:6`](https://github.com/twilightcity-net/flow-insight/blob/872b8ac1decccc17531fcb98e3a8ed1f0053e0ec/src/layout/shared/FeatureToggle.js?plain=1#L6), then update `name`, `productName`, `description` and `build.appId` in `package.json`. Commit `872b8ac1` ("set default config to FlowJournal app") is a worked example of the full edit.
- **Dev:** `yarn dev` runs `react-scripts start` and Electron together, with Electron waiting for port 3000 ([`package.json:37`](https://github.com/twilightcity-net/flow-insight/blob/872b8ac1decccc17531fcb98e3a8ed1f0053e0ec/package.json?plain=1#L37)). The README asks for Node v16.13.0 and Yarn 1.22, and on Apple silicon, `npm_config_arch=x64` ([`README.md:22-25`](https://github.com/twilightcity-net/flow-insight/blob/872b8ac1decccc17531fcb98e3a8ed1f0053e0ec/README.md?plain=1#L22-L25), [`:44-46`](https://github.com/twilightcity-net/flow-insight/blob/872b8ac1decccc17531fcb98e3a8ed1f0053e0ec/README.md?plain=1#L44-L46)).
- **First run** asks for an activation code. The API key is saved to `~/.flow/settings.json`, and the app restarts. In dev it only exits ([`public/app/App.js:390-393`](https://github.com/twilightcity-net/flow-insight/blob/872b8ac1decccc17531fcb98e3a8ed1f0053e0ec/public/app/App.js?plain=1#L390-L393)).
- **Every run** goes through login → Talknet → volumes → console → shortcuts. After that, the heartbeat (60 s), the flow publisher (10 min) and the Fervie help job start ([`public/app/AppLoader.js:237-255`](https://github.com/twilightcity-net/flow-insight/blob/872b8ac1decccc17531fcb98e3a8ed1f0053e0ec/public/app/AppLoader.js?plain=1#L237-L255)).
- **Servers:** the API is `https://home.twilightcity.net` and Talknet is `https://talk.twilightcity.net`, both hard-coded ([`public/app/AppConfig.js:12-13`](https://github.com/twilightcity-net/flow-insight/blob/872b8ac1decccc17531fcb98e3a8ed1f0053e0ec/public/app/AppConfig.js?plain=1#L12-L13)). `dev:local` and `dev:grid` pass `SERVER=`/`TALK=` arguments, but the code that read them is commented out ([`AppConfig.js:27-53`](https://github.com/twilightcity-net/flow-insight/blob/872b8ac1decccc17531fcb98e3a8ed1f0053e0ec/public/app/AppConfig.js?plain=1#L27-L53)).
- **Tests:** `yarn test` runs mocha over `test/**/*Test.js` with the API setup ([`package.json:40`](https://github.com/twilightcity-net/flow-insight/blob/872b8ac1decccc17531fcb98e3a8ed1f0053e0ec/package.json?plain=1#L40)). Separate `test:hyper`, `test:talk` and `test:app` scripts exist ([`package.json:41-43`](https://github.com/twilightcity-net/flow-insight/blob/872b8ac1decccc17531fcb98e3a8ed1f0053e0ec/package.json?plain=1#L41-L43)).
- **Release:** `yarn release` runs build → bundle → electron-builder → GitHub. See the *Build and release* diagram.

## Open questions

- **Which server is production?** The README says `flow.twilightcity.net` ([`README.md:19`](https://github.com/twilightcity-net/flow-insight/blob/872b8ac1decccc17531fcb98e3a8ed1f0053e0ec/README.md?plain=1#L19)), but the code uses `home.twilightcity.net` ([`AppConfig.js:12`](https://github.com/twilightcity-net/flow-insight/blob/872b8ac1decccc17531fcb98e3a8ed1f0053e0ec/public/app/AppConfig.js?plain=1#L12)).
- **Are local servers supported?** The `SERVER=`/`TALK=` handling is commented out, so `yarn dev:local` starts a mock server that the app never calls. The repo doesn't say why it was disabled.
- **Can `DATABASE_VOLUMES_READY` fire more than once?** The counter starts at 1 against a threshold of 7, with 8 callbacks feeding it ([`public/managers/VolumeManager.js:26-37`](https://github.com/twilightcity-net/flow-insight/blob/872b8ac1decccc17531fcb98e3a8ed1f0053e0ec/public/managers/VolumeManager.js?plain=1#L26-L37), [`:176-186`](https://github.com/twilightcity-net/flow-insight/blob/872b8ac1decccc17531fcb98e3a8ed1f0053e0ec/public/managers/VolumeManager.js?plain=1#L176-L186)). It's unclear whether that's intended or whether later firings are harmless.
- **API-key storage.** The AES passphrase is a literal in source ([`public/app/AppSettings.js:45-47`](https://github.com/twilightcity-net/flow-insight/blob/872b8ac1decccc17531fcb98e3a8ed1f0053e0ec/public/app/AppSettings.js?plain=1#L45-L47)), and a nearby FIXME says the crypto is disabled when it isn't ([`AppSettings.js:18`](https://github.com/twilightcity-net/flow-insight/blob/872b8ac1decccc17531fcb98e3a8ed1f0053e0ec/public/app/AppSettings.js?plain=1#L18)).
- **Where releases go.** `package.json` `repository` points at `twilightcity-net/flowinsight-release`, not this repo ([`package.json:17-20`](https://github.com/twilightcity-net/flow-insight/blob/872b8ac1decccc17531fcb98e3a8ed1f0053e0ec/package.json?plain=1#L17-L20)).
- **Which features belong to which app?** No list exists. You have to work it out from the roughly fifty app-type checks. The app menu gives a hint: it offers FlowJournal one toggle ("Focus Bar"), FlowInsight ten, and WatchMoovies none ([`public/app/MenuHandler.js:13-120`](https://github.com/twilightcity-net/flow-insight/blob/872b8ac1decccc17531fcb98e3a8ed1f0053e0ec/public/app/MenuHandler.js?plain=1#L13-L120)).
- **Two copies of the app type.** The main process and renderer each declare it, and nothing checks that they agree. A TODO says they "should exist on the backend, and be handed to the frontend so they're in one place" ([`src/layout/shared/FeatureToggle.js:3-4`](https://github.com/twilightcity-net/flow-insight/blob/872b8ac1decccc17531fcb98e3a8ed1f0053e0ec/src/layout/shared/FeatureToggle.js?plain=1#L3-L4)).
- **The IDE plugins** that write `~/.flow/plugins/*/active.flow` aren't in this repo, and the feed format isn't documented here.
